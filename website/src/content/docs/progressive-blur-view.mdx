`ProgressiveBlurView` renders a variable/gradient blur that transitions smoothly instead of applying a uniform blur intensity. It works on **iOS, Android, and Web**, though the underlying implementations differ:

- **iOS**: private Core Animation filters for true variable blur.
- **iOS accessibility**: Reduce Transparency switches to `reducedTransparencyFallbackColor` immediately, including changes while mounted. Turning it off restores the configured blur without changing the children.
- **Android**: Android 12 and later ramp the blur radius on the GPU. Android 11 and earlier use QmBlurView's `BlurView`, which fades one blur out with a gradient mask.
- **Web**: stacks several CSS `backdrop-filter` layers with gradient masks, halving the radius per layer — a genuine blur-radius ramp (from `blurAmount` px down to sharp), not a single blur fading in opacity.

On web, `blurAmount` is the maximum radius in px (matching native), and browsers without `backdrop-filter` fall back to the directional tint gradient alone. Since 6.0, `startOffset` means the same thing on every platform — see [Platform differences](#platform-differences) for how the fade is constructed per backend.

## Basic usage

```tsx
import { ProgressiveBlurView } from '@sbaiahmed1/react-native-blur';

<ProgressiveBlurView
  blurType="light"
  blurAmount={30}
  direction="blurredTopClearBottom"
  startOffset={0}
  style={{ height: 200 }}
>
  <Text>Progressive blur from top (blurred) to bottom (clear)</Text>
</ProgressiveBlurView>
```

## Center blur

`direction="blurredCenterClearTopAndBottom"` creates a blur body that peaks in the center and fades to clear at both edges.

```tsx
<ProgressiveBlurView
  blurType="regular"
  blurAmount={35}
  direction="blurredCenterClearTopAndBottom"
  startOffset={0} // keep 0 for the longest blur body; raise toward 0.3 to shorten it
  style={{ height: 220, borderRadius: 16 }}
>
  <Text>Clear at top</Text>
  <Text>Blurred at center</Text>
  <Text>Clear at bottom</Text>
</ProgressiveBlurView>
```

## Top and bottom blur

`direction="blurredTopAndBottomClearCenter"` blurs the top and bottom edges and leaves the middle clear, the reverse of the center blur. Put it over a scroll view to soften the content at both edges:

```tsx
<View style={{ height: 320 }}>
  <ScrollView>{rows}</ScrollView>
  <ProgressiveBlurView
    blurType="regular"
    blurAmount={20}
    direction="blurredTopAndBottomClearCenter"
    startOffset={0.05} // a fully blurred band of 5% at each edge, up to 0.3
    style={StyleSheet.absoluteFill}
    pointerEvents="none"
  />
</View>
```

## Locked content / paywall pattern

```tsx
<View style={{ position: 'relative' }}>
  <Text>Long content here...</Text>

  <ProgressiveBlurView
    blurType="light"
    blurAmount={20}
    direction="blurredBottomClearTop"
    startOffset={0.5} // bottom half fully blurred, fade over the top half
    style={{ position: 'absolute', bottom: 0, left: 0, right: 0, height: 200 }}
  >
    <Text>🔒 Unlock to read more</Text>
    <Button title="Purchase" />
  </ProgressiveBlurView>
</View>
```

## Platform differences

The three backends aim for the same look but get there differently:

- **Blur ramp.** iOS and Web ramp the blur *radius* from `blurAmount` down to 0 across the gradient. Android 12 and later ramp the radius along the same curve, but the same `blurAmount` gives a lighter blur than on iOS. Android 11 and earlier render one fixed-radius blur and ramp its *opacity* with an eased mask, and blur the center direction at about a third of `blurAmount`.
- **`startOffset`** means the same thing on every platform. For the edge directions it grows a fully blurred plateau from the blurred edge: `0.4` means the nearest 40% of the view is uniformly blurred and the fade spans the remaining 60%. For the center direction it insets the fade start from the edges (clamped to 0.3), which shortens the blur body, so `0` gives the longest body. For the top and bottom direction it sets the fully blurred band at each edge (clamped to 0.3).

## Android backend notes

On Android 12 and later, the blur reads the views drawn behind it and blurs them on the GPU. On Android 11 and earlier, QmBlurView captures the view tree around it into a downsampled bitmap and blurs it on the CPU. The capture covers the nearest `react-native-screens` Screen, or the React root when there is none.

- **`blurRounds` only changes Android 11 and earlier.** Each iteration adds a CPU blur pass. Lowering it trades quality for less work, so measure on target devices.
- **Foreground content stays out of the blur on Android 12 and later.** This component's children render sharp above the masked blur on every version. On Android 11 and earlier, other foreground siblings inside the capture root can still produce a blurred halo. If necessary, move those siblings outside the capture root (e.g. a portal above the navigator).
- **Blur and glass views show each other on Android 12 and later.** Where two of them overlap, the top one shows the one below it, with its text and tint.
- **The blur falls back to a screen capture if the library cannot read the views behind it.** The library then logs a warning tagged `RNBackdrop`. Other foreground siblings show as a halo, as on Android 11 and earlier, and overlapping blur and glass views leave each other out.
